// 01 — Introducción

¿Qué es Git?

Git es un sistema de control de versiones distribuido. Piénsalo como una máquina del tiempo para tu código: guarda cada cambio que haces, te permite volver atrás, trabajar en paralelo con otras personas y nunca perder nada.

📸

Commits

Fotografías de tu proyecto en un momento exacto. Cada commit tiene un mensaje que describe qué cambiaste.

🌿

Branches (Ramas)

Líneas paralelas de desarrollo. Puedes trabajar en una función nueva sin afectar el código principal.

🗂️

Repositorio

La carpeta especial donde Git guarda todo el historial de tu proyecto. Puede ser local o en GitHub.

🔀

Merge

Fusión de dos ramas. Combina los cambios de distintas ramas en una sola.

☁️

Remote

Versión de tu repositorio alojada en la nube (GitHub, GitLab). Permite colaborar y hacer backups.

📦

Staging Area

Zona intermedia donde preparas los archivos que van al próximo commit. Como armar una caja antes de enviarla.

📥

Clone

Copia completa de un repositorio remoto descargada en tu máquina local, incluyendo todo su historial de commits y ramas.

🙈

.gitignore

Archivo de texto que le indica a Git qué archivos o carpetas debe ignorar completamente, como node_modules/ o archivos .env con contraseñas.

// 03 — Conceptos clave

Las 4 zonas de Git

Git y GitHub juntos operan en 4 zonas distintas. Dominar este mapa mental es la clave para no perderte con ningún comando.

💡 ¿Por qué 4 zonas? La guía original mostraba 3 zonas locales, pero Git en la práctica —como lo explica el video de Fazt— involucra siempre una cuarta: el repositorio remoto en GitHub. Sin ella no hay colaboración ni respaldo en la nube.

// ZONA 1 — Working Directory

Tu carpeta de trabajo normal. Aquí editas archivos con tu editor. Git los ve pero no los rastrea automáticamente.

// ZONA 2 — Staging Area (Índice)

Zona de preparación. Usas git add para seleccionar exactamente qué cambios incluirás en el próximo commit.

// ZONA 3 — Repositorio local (.git)

La base de datos interna de Git. git commit graba aquí una instantánea permanente con su hash único.

// ZONA 4 — GitHub (Remoto)

Servidor en la nube. git push sube tus commits; git pull baja los de tus compañeros. Aquí ocurre la colaboración.

Estados de un archivo

Cada archivo en Git puede estar en uno de estos estados:

estados-de-archivo.sh
# Untracked — Git no conoce este archivo aún
$ git status
Untracked files: nuevo-archivo.txt

# Staged — listo para el commit
$ git add nuevo-archivo.txt
Changes to be committed: new file: nuevo-archivo.txt

# Committed — guardado en el historial
$ git commit -m "mi primer archivo"
1 file changed, 0 insertions(+), 0 deletions(-)

# Modified — fue editado después del último commit
modified: nuevo-archivo.txt

// 05 — Flujo de trabajo

El ciclo completo

Flujo de trabajo tal como lo muestra Fazt en su curso: desde crear una rama para una nueva función, hasta fusionarla en main y subirla a GitHub.

// CICLO TÍPICO EN EL VIDEO DE FAZT

El video enseña el flujo: status → checkout -b → editar → add → commit → checkout main → merge → push. Este es el ciclo real de un desarrollador trabajando con ramas.

flujo-completo-fazt.sh
# ── PASO 1: Verifico en qué rama estoy y el estado ──
$ git status
On branch main
nothing to commit, working tree clean

# ── PASO 2: Creo y cambio a una rama nueva para la feature ──
# Buena práctica de Fazt: nunca trabajar directo en main
$ git checkout -b feature/login
Switched to a new branch 'feature/login'

# ── PASO 3: Edito/creo archivos con mi editor ──
# (aquí escribes tu código en VS Code, Sublime, etc.)
$ git status
On branch feature/login
Untracked files: login.html

# ── PASO 4: Agrego los archivos al staging ──
$ git add .
$ git status
Changes to be committed:
new file: login.html

# ── PASO 5: Hago el commit con mensaje descriptivo ──
# Fazt recomienda mensajes cortos y en inglés o español claro
$ git commit -m "feat: agregar formulario de login"
[feature/login 3a1b2c4] feat: agregar formulario de login
1 file changed, 35 insertions(+)

# ── PASO 6: Regreso a main y fusiono la rama ──
$ git checkout main
Switched to branch 'main'
$ git merge feature/login
Updating f3e4d2a..3a1b2c4 Fast-forward
login.html | 35 ++++++++++++++++++++++++++

# ── PASO 7: (Opcional) Elimino la rama ya fusionada ──
$ git branch -d feature/login
Deleted branch feature/login (was 3a1b2c4).

# ── PASO 8: Subo los cambios a GitHub 🚀 ──
$ git push origin main
Branch 'main' set up to track remote branch 'main' from 'origin'.
✓ Cambios en producción
// 06 — Ejemplo práctico

Tu primer repositorio

Vamos paso a paso. Al finalizar tendrás un proyecto en GitHub. Cada paso muestra los comandos en paralelo para CMD (Windows) y Bash (Linux/Mac/Git Bash).

// ¿CMD o Bash?

CMD es el símbolo del sistema de Windows (Win + R → cmd). Bash es la terminal de Linux, macOS o Git Bash en Windows. Git funciona igual en ambos; la diferencia está en algunos comandos del sistema operativo como crear archivos o carpetas.

1

Configura Git por primera vez

Solo se hace una vez. Establece tu nombre y correo para que los commits queden firmados.

configuraciónCMD
REM Configura nombre y correo
C:\> git config --global user.name "Tu Nombre"
C:\> git config --global user.email "tu@email.com"
C:\> git config --list
user.name=Tu Nombre
user.email=tu@email.com
core.autocrlf=true
configuraciónBash
# Configura nombre y correo
$ git config --global user.name "Tu Nombre"
$ git config --global user.email "tu@email.com"
$ git config --list
user.name=Tu Nombre
user.email=tu@email.com
core.repositoryformatversion=0
// ¿Qué hace git config --list?

git config --list imprime en la terminal todas las configuraciones que Git tiene activas en ese momento, combinando tres niveles: sistema (para todos los usuarios del PC), global (para tu usuario, archivo ~/.gitconfig) y local (solo para el repositorio actual, archivo .git/config). Es el comando de diagnóstico número uno: si Git no tiene tu nombre, no sabe tu email, o usa el editor equivocado, aquí lo ves. También aparecen configuraciones automáticas del sistema como core.autocrlf o el editor por defecto.

2

Crea la carpeta del proyecto

Crea una carpeta nueva y entra en ella. Aquí vivirá tu proyecto. Los comandos del sistema operativo difieren entre CMD y Bash.

crear carpetaCMD
C:\Users\tú> mkdir mi-primer-proyecto
C:\Users\tú> cd mi-primer-proyecto
C:\...\mi-primer-proyecto> cd
C:\Users\tú\mi-primer-proyecto
crear carpetaBash
$ mkdir mi-primer-proyecto
$ cd mi-primer-proyecto
~/mi-primer-proyecto$ pwd
/home/usuario/mi-primer-proyecto
3

Inicializa el repositorio

Este comando crea la carpeta oculta .git donde Git guardará todo el historial. Funciona igual en ambos entornos.

git initCMD
C:\...\mi-primer-proyecto> git init
Initialized empty Git repository in
C:/Users/tú/mi-primer-proyecto/.git/

C:\...\mi-primer-proyecto> dir /a
.git ← carpeta oculta de Git
git initBash
$ git init
Initialized empty Git repository in
/home/usuario/mi-primer-proyecto/.git/

$ ls -la
drwxr-xr-x .git ← aquí vive Git
4

Crea tu primer archivo

Crea un archivo README.md. Aquí CMD y Bash difieren notablemente en cómo crean y escriben archivos desde la terminal.

crear archivoCMD
REM En CMD se usa echo y redirección
C:\...> echo # Mi Primer Proyecto > README.md
C:\...> echo Hola Git! >> README.md
C:\...> type README.md
# Mi Primer Proyecto
Hola Git!
crear archivoBash
# En Bash también funciona echo
$ echo "# Mi Primer Proyecto" > README.md
$ echo "Hola Git!" >> README.md
$ cat README.md
# Mi Primer Proyecto
Hola Git!
5

Agrega el archivo al staging

Con git add le dices a Git qué archivos quieres incluir en el próximo commit. Este comando es idéntico en CMD y Bash.

git addCMD
C:\...> git status
Untracked files: README.md

C:\...> git add README.md
C:\...> git status
Changes to be committed:
new file: README.md
git addBash
$ git status
Untracked files: README.md

$ git add README.md
$ git status
Changes to be committed:
new file: README.md
6

Haz tu primer commit

El commit guarda permanentemente los cambios con un mensaje descriptivo. Comando idéntico en ambos entornos.

git commitCMD
C:\...> git commit -m "feat: primer commit"
[main (root-commit) a1b2c3d]
feat: primer commit
1 file changed, 2 insertions(+)

C:\...> git log --oneline
a1b2c3d feat: primer commit
git commitBash
$ git commit -m "feat: primer commit"
[main (root-commit) a1b2c3d]
feat: primer commit
1 file changed, 2 insertions(+)

$ git log --oneline
a1b2c3d feat: primer commit
7

Conéctalo a GitHub y sube el código

Crea un repositorio vacío en github.com, luego conecta tu repo local con el remoto y sube todo. Comandos idénticos en ambos entornos.

push a GitHubCMD
REM Conecta tu repo local con GitHub
C:\...> git remote add origin https://github.com/tú/mi-proyecto.git

C:\...> git remote -v
origin https://github.com/tú/mi-proyecto.git (fetch)
origin https://github.com/tú/mi-proyecto.git (push)

C:\...> git push -u origin main
Writing objects: 100% (3/3), done.
Branch 'main' tracks origin/main ✓
push a GitHubBash
# Conecta tu repo local con GitHub
$ git remote add origin https://github.com/tú/mi-proyecto.git

$ git remote -v
origin https://github.com/tú/mi-proyecto.git (fetch)
origin https://github.com/tú/mi-proyecto.git (push)

$ git push -u origin main
Writing objects: 100% (3/3), done.
✓ Tu proyecto está ahora en GitHub!

// 08 — GitHub

De local a la nube

GitHub es la plataforma más popular para alojar repositorios Git, colaborar con otros desarrolladores y mostrar tu trabajo al mundo.

🍴

Fork

Copia de un repositorio ajeno en tu cuenta de GitHub. Puedes modificarlo sin afectar el original.

🔃

Pull Request

Solicitud para que el dueño del repo original incorpore tus cambios. Es la base de la colaboración open source.

⭐

Stars & Watch

Marcar un repo como favorito o seguirlo para recibir notificaciones de cambios importantes.

🐛

Issues

Sistema de tickets para reportar bugs, proponer mejoras o discutir cambios en un proyecto.
